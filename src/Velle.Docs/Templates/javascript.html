Architecture · Velle.Blazor

Alpine & Interop

Velle.Blazor pairs Blazor Static SSR with a locally bundled Alpine.js CSP build loaded automatically via Blazor's JavaScript initializer — zero unsafe-eval, zero manual script tags, and clean synchronization across enhanced navigation and form posts.

Automatic JS initializer

ASP.NET Core Blazor automatically discovers and runs _content/Velle.Blazor/Velle.Blazor.lib.module.js whenever blazor.web.js starts. In afterWebStarted(blazor), Velle:

  • Uses an existing window.Alpine if your app loaded Alpine itself, or exposes Velle's bundled Alpine.js CSP build on window.Alpine.
  • Registers the velleDialog, velleTabs, and velleDatepicker Alpine data components.
  • Dispatches velle:before-start on window so your app can register custom Alpine components or stores before startup.
  • Starts Alpine once (guarded against double initialization) and wires Blazor's enhancedload event to dispatch velle-enhanced-load.

Enhanced navigation & form sync

When a user navigates via an enhanced link or submits an EditForm Enhance, Blazor patches the DOM in place without reloading the page. Alpine components rendered by Velle listen to x-on:velle-enhanced-load.window="refresh" so client widgets stay aligned with the server:

ComponentSync behavior on velle-enhanced-load
VelleDialogReads data-velle-open from the server response, opens or closes the native modal safely, and clears data-velle-open on native close events (Escape, backdrop click, or <form method="dialog">).
VelleTabsPreserves client-side tab selection while still honoring updated server data-velle-selected values and keeping ARIA attributes consistent.
VelleDatepickerRebuilds the lazy-loaded Flatpickr instance from the server-rendered defaultValue, syncs aria-invalid/validation classes onto the visible display input, and destroys the calendar cleanly when navigating away.

Extending Alpine.js

Listen for velle:before-start to register your own CSP-safe Alpine components or stores on the same Alpine instance before Alpine.start() runs:

js 
window.addEventListener("velle:before-start", ({ detail: { Alpine } }) => {
  Alpine.data("myCounter", () => ({
    count: 0,
    increment() {
      this.count++
    },
  }))
})

Because Velle ships the Alpine.js CSP build, define methods and computed getters inside Alpine.data(...) and bind them by name (e.g. x-on:click="increment", x-text="count") instead of inline JS expressions.

Legacy velle.js runtime

The reference below applies to the legacy framework-agnostic Velle.Tool CLI and dist/velle.js bundle. New Blazor apps should use Velle.Blazor and Alpine.js CSP above.

Loading

Every legacy behavior is an ES module that imports ./velle.js:

<script type="module" src="https://cdn.jsdelivr.net/gh/codedbyshoe/velle-css@v{{ escape_html page.Site.Version }}/dist/velle.js"></script>

Using the JavaScript without the CSS

dotnet tool run velle init --js           # writes velle.json and main.js, and no styles
dotnet tool run velle add tabs menu       # copies only their JavaScript
dotnet tool run velle new controller cart # or start from the bare runtime

Writing your own controllers

Use controller({ targets, values }) as the base class for legacy runtime controllers:

<div data-counter>
  <output data-counter-target="output"></output>
  <button data-counter-action="increment">Add to cart</button>
</div>

<nav data-cart data-cart-count="0" data-cart-action="velle:counter:change@window->refresh">
  <span class="badge" data-cart-target="badge"></span>
  <span data-cart-target="total"></span>
</nav>
// @ts-check
import { define, controller } from "./velle.js"

define("counter", class extends controller({
  targets: { output: HTMLElement },
  values: { count: 0 },
}) {
  connect() {
    this.countChanged()
  }

  increment() {
    this.count++
  }

  countChanged() {
    const { output } = this.$
    if (output) output.textContent = String(this.count)
    this.dispatch("change", { count: this.count })
  }
})

define("cart", class extends controller({
  targets: { badge: HTMLElement, total: HTMLElement },
  values: { count: 0, url: "/cart/total" },
}) {
  connect() {
    this.on(document, "visibilitychange", () => this.#loadTotal())
    this.countChanged()
  }

  /** @param {CustomEvent<{ count: number }>} event */
  refresh(event) {
    this.count = event.detail.count
  }

  countChanged() {
    const { badge } = this.$
    if (badge) badge.textContent = String(this.count)
    this.#loadTotal()
  }

  async #loadTotal() {
    try {
      const response = await fetch(this.url, { signal: this.signal })
      const { total } = this.$
      if (total) total.textContent = await response.text()
    } catch (error) {
      if (!this.signal.aborted) throw error
    }
  }
})
